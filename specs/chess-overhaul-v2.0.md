# Chess UI rewrite: DOM/CSS/SVG board, game menu, full-screen app

## Context

`/chess/` today is `src/pages/chess.astro` + the frozen `public/js/chess-game.js` (791 lines). That file draws the whole board on two `<canvas>` elements with Unicode glyphs, takes clicks only, teleports pieces, has no menu (just a difficulty number field and a checkbox), and gets cramped on phones. The user wants a modern rewrite of the **presentation layer**. It should run as a static Astro page on GitHub Pages and have these features:

- a main menu: vs robot with level selection, 2 players on one device, and "2 players via link/QR" shown as *coming soon* (the relay server is out of scope)
- CSS-drawn board, SVG pieces, drag **and** click, pieces that animate when they move
- mobile-optimized layout
- official notation (SAN) in the history, as an option
- extras (all approved): play as Black or random color, sound effects, board and piece themes, PGN copy, and a win effect

**Decisions made with the user:**

- DOM + CSS + SVG. **No PixiJS:** a 64-square board gains nothing from WebGL, Pixi would add 150 KB+ and lose accessibility, and CLAUDE.md asks for vanilla code.
- A full-screen game shell instead of the blog layout.
- Rules engine from the npm `chess.js`, pinned to the same version as the vendored copy. `chess-game.js` and `public/js/chess.js(.map)` are retired after the new page works.

**Not touched:** the rules (chess.js), `public/js/StockfishWeb.js`, and `stockfish.*`. The game-flow functions (`doMove`, `handleGameState`, `undoMove`, `surrenderGame`, save/restore) are **ported faithfully** to TypeScript. They change only where a new feature needs it (robot plays first when the human is Black). Logic bugs found in the review are **not fixed here**: they go to a separate bug list (see the end of this plan).

## Architecture

```text
src/pages/chess.astro                 # rewritten: GameLayout + menu screen + game screen + dialogs
src/layouts/GameLayout.astro          # new: <html> shell, BaseHead (SEO/fonts/global.css), no Header/Footer, 100dvh app body
src/components/chess/
  GameMenu.astro                      # mode tiles, level slider, color picker, "Continue game" when a save exists
  ChessBoard.astro                    # board container markup (squares are generated by JS)
  GamePanel.astro                     # player strips (name, captured pieces, +material), history, action bar
  ChessDialogs.astro                  # <dialog>s: promotion, confirm (surrender/new game), game over, settings
src/assets/chess/pieces/cburnett/*.svg   # 12 SVGs (wK..bP), Wikimedia cburnett set, BSD/GPL/GFDL triple licence
src/assets/chess/pieces/chessnut/*.svg   # 2nd set, Chessnut (Apache-2.0, as used on Lichess)
src/scripts/chess/
  main.ts          # entry: reads prefs, wires menu <-> game screens, dialogs, buttons
  game.ts          # GameController: port of chess-game.js flow (move, robot turn, game state, undo, surrender, save/restore)
  engine.ts        # typed wrapper around the global StockfishWeb (+ stockfish-web.d.ts); lazy init, awaited ready, "thinking" state
  board-view.ts    # DOM board: squares, piece layer, highlights, orientation, animation, pointer + keyboard input
  notation.ts      # move formatting (figurine SAN / SAN / coordinates), history list, captured pieces + material diff
  effects.ts       # Web Audio synthesized sounds (move/capture/check/end) + small CSS confetti
  prefs.ts         # localStorage prefs + saved game, every access in try/catch
```

- Load the code with a normal processed `<script>import '../scripts/chess/main.ts'</script>` (Astro bundles and hashes it). Keep only `<script is:inline src="/js/StockfishWeb.js">` as an inline script. The worker path `/js/stockfish.wasm.js` (or `/js/stockfish.js` when WebAssembly is missing) does not change.
- `pnpm add chess.js@<exact version>`. To find the version, diff `node_modules/chess.js/dist/esm/chess.js` against `public/js/chess.js` (the Peggy 4.2.0 header points to 1.2–1.4; check candidates until they match).
- No other runtime dependencies.

## Board rendering (board-view.ts + ChessBoard.astro CSS)

- **Squares:** a CSS grid of 64 `<button>`s in an `aspect-ratio: 1` container. Colors come from `--sq-light` / `--sq-dark` per theme (`[data-board="wood|green|blue|slate"]`). Highlights are classes: `.last-move`, `.selected`, `.check` (radial red glow on the king), `.target` (a dot, via `::after`) and `.target.capture` (a ring). Rank and file coordinates sit inside the edge squares, lichess style, and follow the board orientation. This replaces the outer canvas gutter.
- **Pieces:** an absolutely positioned layer of `<div class="piece" data-piece="wN">` elements, each 12.5% of the board size. Each piece is placed with `translate: calc(var(--x) * 100%) calc(var(--y) * 100%)`. The image is `background-image: var(--wN)`, and each piece set defines those variables under `[data-pieces="cburnett|chessnut"]` with relative `url(...)` that Vite fingerprints.
- **Animation:** piece elements keep their identity (a square→element map). `applyMove(move)` changes `--x/--y` on the moving element, and a CSS `transition: translate 180ms` animates it. It also handles the capture (fade and remove), castling (moves the rook too), en passant (removes the pawn) and promotion (swaps `data-piece`). Undo animates in reverse. New game and restore call `setPosition(board)` with no animation. `prefers-reduced-motion` already disables transitions globally.
- **Input (Pointer Events, works for mouse and touch):**
  - `pointerdown` on one of your own pieces selects it and shows legal targets (`game.moves({ square, verbose: true })`).
  - If the pointer moves more than about 4 px (more on `pointer: coarse`), the drag starts: `setPointerCapture`, the piece follows the pointer, is scaled up and casts a shadow, and the square under the pointer is outlined.
  - On `pointerup` over a legal target the move is made and the piece snaps. Anywhere else it animates back.
  - Click-then-click still works.
  - The board has `touch-action: none`.
  - Input is accepted **only on a human's turn**, so the board is locked while the robot thinks.
- **Keyboard and screen readers:** roving tabindex over the squares, with arrow keys to move and Enter/Space to select and move. Each square has an `aria-label` such as "e4, white knight". An `aria-live` status line announces moves, check and the result.
- **Orientation:**
  - vs robot: the board is flipped when the human plays Black.
  - 2 players: a pref with two values. "Face to face" (the default, today's behavior) draws Black's pieces rotated 180° for tabletop play. "Flip each move" turns the board after each move.
  - A flip button sits in the action bar.
- **Promotion:** a small `<dialog>` docked over the promotion file shows the 4 pieces in the current piece set. Esc or a click on the backdrop cancels and returns the pawn.

## Game flow (game.ts — port of chess-game.js)

- `GameController` holds the `Chess` instance and the mode `{ kind: 'robot' | 'local', level, humanColor }`, and calls back into the view and panel (`onMove`, `onState`, `onThinking`, `onGameOver`).
- Ported **as-is**:
  - `doMove`: promotion handling, then `move()`, then the robot reply when it is the robot's turn, then save
  - `handleGameState`: capture, promotion, check and game-over messages; results `1-0` / `0-1` / `1/2-1/2`
  - `undoMove`: two plies, as today
  - `surrenderGame`
  - `saveGameState` / `loadSavedGame`: same `chess_game_state` key and `{ pgn, difficulty, withRobot }` fields, plus new optional `mode` and `humanColor`, so games saved by the old page still restore
- **New, needed for the requested features:**
  - When the human is Black, or the color is random and comes up Black, the robot moves first, both at game start and after a restore.
  - Undo stops on the human's turn. If it ends on the robot's turn, for example by undoing the robot's first move as White, the robot moves again.
  - The game-over card names the reason using chess.js predicates: checkmate, stalemate, threefold repetition, insufficient material or the fifty-move rule.
- **Engine (engine.ts):** create one StockfishWeb on first need. `await init()` and `setEngineDifficulty(level)` before the board is enabled. The old unawaited warm-up `getBestMove('e2e4')` is dropped (see bug #3). Show a "Robot is thinking…" indicator while `getBestMoveFen` runs.
- **Levels:** a range slider from 0 to 20, the same values passed to `setEngineDifficulty`. Named bands are shown under it: Beginner 0–3, Casual 4–7, Club 8–11, Strong 12–15, Master 16–20.

## Menu and screens (GameMenu.astro, main.ts)

- **Menu screen:** a title and four large tiles.
  1. **Play vs Robot:** level slider, then color (White / Black / Random), then *Start*.
  2. **2 Players – this device:** orientation choice, then *Start*.
  3. **2 Players – send link / QR:** disabled, with a "Coming soon" badge.
  4. **Continue game:** shown only when a save exists, with a summary such as "vs Robot L5, move 14".
- **Game screen:** the screen swap uses the View Transitions API (`document.startViewTransition`) when the browser supports it and is instant otherwise.
- **Settings dialog:** board theme, piece set, notation, sound on/off and the 2-player orientation. Saved in prefs under the `chess_prefs` key.
- **Top bar:** "← Games" (`/games/`), the game title, and buttons for settings and the menu. The menu button asks for confirmation if a game is in progress. The hit-counter image moves to the bottom of the menu screen.

## Layout and mobile

- `GameLayout` uses `min-height: 100dvh`, safe-area insets and its own palette: a dark table background with warm accents, light/dark aware through tokens defined in the page's `:root` scope.
- **Board size:** `--board: min(100vw - 2*gutter, 100dvh - topbar - strips - actionbar)`, so the board is never clipped and the page never scrolls sideways.
- **Landscape / desktop (min-aspect-ratio 1/1 and enough width):**
  - left: the board between the opponent strip (top) and the player strip (bottom)
  - right: a side panel with the history, then the actions (Undo, Flip, Copy PGN, Surrender, New game)
- **Portrait / phone:** top bar, opponent strip, board edge to edge, player strip, a horizontally scrolling history strip (the current move scrolls into view), and a sticky action bar with icon buttons and 44 px+ tap targets.
- "Detect mobile" is done with media queries (`orientation`, `pointer: coarse`, `hover: none`) instead of user-agent sniffing. JS reads `matchMedia('(pointer: coarse)')` only for the drag threshold.

## History and notation (notation.ts)

- Moves come from `history({ verbose: true })`.
- **Notation formats** (a toggle in the panel header, remembered in prefs):
  - **Figurine SAN** (the default; official algebraic with piece icons): `1. e4 e5 2. ♘f3 ♞c6 … O-O, exd5, e8=♕+, #`
  - **SAN** (letters): `Nf3`
  - **Coordinates** (the old style): `♘ g1–f3`
- **Captured pieces:** each player strip shows the pieces it has captured as small SVGs, plus a material advantage such as "+3".
- **Copy PGN:** `navigator.clipboard.writeText(game.pgn())` with headers (Event, Date, White/Black = "You" / "Stockfish L5", Result), and a confirmation toast.

## Effects (effects.ts)

- **Sounds:** synthesized with Web Audio (short oscillator and noise envelopes for move, capture, check and game end), so there are no audio files and no license questions. The `AudioContext` is created on the first user gesture and is muted by default.
- **Win effect:** about 40 lines of CSS confetti (absolutely positioned spans with randomized keyframes, removed when the animation ends). It plays when a human wins, and the result card appears with *Play again* and *Menu*.
- **Toasts:** reuse the existing queue idea (one message per second, each lives 3 s) in a `popover="manual"` container, plus the persistent `aria-live` status line.

## Bugs found in the review: file separately, don't fix in this pass

Write them to `specs/chess-known-issues.md` (`gh` is not installed, so the user can turn them into GitHub issues):

1. **Engine replies can cross-resolve.**
   - What happens: `StockfishWeb.send` listens for a token, so concurrent calls waiting on the same `bestmove`/`readyok` resolve each other. With the unawaited warm-up `getBestMove('e2e4')` in `initStockfishWeb`, a quick first move can receive the warm-up's answer.
   - Effect: an illegal move that `doMove`'s `catch` swallows, leaving the game stuck on the robot's turn.
   - Status: the new code avoids it by awaiting init and dropping the warm-up. The root cause in `StockfishWeb.js` stays.
2. `doMove` swallows every error, including engine failures and a null `bestmove`, so the game can freeze silently.
3. The board accepts input while the robot is thinking: you can move Black's pieces or press Undo in the middle of a search. The new UI locks the board, so this is listed for the record.
4. Undo in 2-player mode reverts two plies, both players' moves, instead of one.
5. If fewer than 2 plies exist, undo pops one, then reports "Nothing to undo" and returns before updating the history and saving.
6. The capture and promotion toasts always show the white glyph (`pieceToUtf8Image.get(move.captured)` ignores the color).
7. `console.log` is replaced with a no-op for the whole page unless `?debug` is set.
8. The surrender dialog says "to the robot" in 2-player mode, and the loser is always the side to move.
9. The promotion modal has no cancel, so the game is stuck until a piece is chosen.
10. Minor: the "No winers" typo, and the hit counter still counts the old `chess.html` URL.
